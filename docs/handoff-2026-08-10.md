# Handoff: site changes affecting the data pipeline
Date: 2026-08-10
Audience: data / pipeline agents producing `weekly_report`, `monthly_report`, and neighborhood payloads.

This lists only the site-side changes that have implications for the feed. Nothing here requires a
pipeline change to keep the site rendering, but several items are workarounds the site should be able
to drop once the feed is corrected.

## 1. Tier shape is now auto-detected, not assumed

The feed has been arriving in two different shapes across months:

- `bands`: Luxury, Prime, Trophy are mutually exclusive price bands. Luxury + Prime + Trophy = segment total.
- `nested`: Prime and Trophy sit inside Luxury. Luxury alone = segment total.

The site now detects the shape per period (`tierShape()` in `src/routes/monthly.tsx`) and adjusts both
the reconciliation check and the explanatory copy. When neither test passes, the shape is `unknown` and
the page says the figures are shown as reported.

**Ask:** pick one model and stay in it, or add an explicit field, for example
`tiers.model: "bands" | "nested"`, on every period. The detection is a heuristic and will
misclassify when counts coincide.

## 2. Reconciliation notes are internal only

The "Checked / Check flagged" line is no longer public.

- The Month: `TierTotalCheck` renders only for signed-in admins (`useAdminRole`).
- The Week: gated behind `ReportBodyOpts.showChecks`, default `false`.

If you need a visible signal that a period failed reconciliation, it has to come through the pipeline
(alerting or `pipeline_run_status`), not the public page.

## 3. `sowhat.trophy_read` can contradict the counts

For week of 2026-08-03 the payload carried `hero.trophy_count = 2` and a trophy series entry of
2 contracts / $59M, but `sowhat.trophy_read` still read "No trophy ($18M+) contracts this week." The
identical string appears on 2026-07-27, which genuinely had 0, so the generator appears to carry the
prior week's sentence forward when it should regenerate.

The site now guards this: when the count is greater than zero and the prose starts with "No trophy,"
The Week rebuilds the sentence from `hero.trophy_count` and the trophy volume.

**Ask:** regenerate `trophy_read` from the same numbers that feed `hero.trophy_count`. The guard is a
patch, not a fix, and it only covers this one contradiction direction.

## 4. `sowhat.discount_read` has no numeric counterpart

`discount_read` ships as finished prose, for example "On closed luxury sales, negotiating room is
steady (avg discount -8.07%)." There is no matching numeric field anywhere in the payload:
`market_pulse.all` has no `discount_pct` at the all-Manhattan level, so the site cannot verify,
re-express, or chart the number, and cannot state the sample size or the window.

**Ask:** add structured fields alongside the prose, ideally:
`discount_pct` (number), `discount_n` (closed sales in the sample), `discount_window`
(for example `52w_trailing`), and `discount_basis` (`original_ask` or `last_ask`). Once those exist the
site can display "n = X closed sales, trailing 52 weeks" and drop its dependence on the sentence.

The same applies in principle to the other `sowhat.*_read` strings: prose without the underlying
numbers cannot be audited or re-styled on the site.

## 5. Weekly language is 52-week trailing, not TTM

The Week now mirrors The Month structurally (segment total bar, collapsible trailing detail panel,
tier cards) but all trailing language on the weekly report is "52-week trailing," never
"trailing twelve month." Weekly trailing median and DOM are computed count-weighted from `tier_series`
because the feed does not supply them directly.

**Ask:** if trailing median price, PPSF, and DOM can be supplied per tier per week, the site can stop
deriving them. Derived values will drift from anything the pipeline publishes elsewhere.

`tier_series` counts and volumes are consumed as already exclusive-band (server-side subtraction done).
Do not change that without telling us, and see item 1.

## 6. Luxury qualification threshold

`MIN_QUALIFIED_LUX_CONTRACTS = 11` in `src/lib/sowhat.ts`. A neighborhood needs at least 11 luxury
contracts over the trailing 52 weeks to be eligible for ranking or So What commentary. The hidden
`/lux-registry` page shows the qualifying set. If the pipeline ranks neighborhoods anywhere, use the
same floor or the two surfaces will disagree.

## 7. Bedroom labels are canonicalized on the site

`src/lib/bedroom-labels.ts` maps feed aliases to a canonical set (for example "Studio/Other" to
"Studio"). Consistent labels from the feed would let us delete that mapping.

## 8. Database

`public.quarterly_brief_publish_log` now has row level security enabled with no policies and
privileges revoked from `anon` and `authenticated`. Service-role writes are unaffected. Anything
writing to it with a publishable/anon key will now fail.

## Priority order for the data side

1. Structured `discount_pct` and friends (item 4). Currently unauditable.
2. Regenerate `trophy_read` (item 3). Live contradiction between prose and counts.
3. Explicit `tiers.model` field (item 1). Removes a heuristic.
4. Per-tier trailing median / PPSF / DOM on the weekly (item 5). Removes derivation drift.
